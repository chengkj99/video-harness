# 面向陌生观众的剪辑审查

目标是让首次看到讲者的人更早理解问题和收益，同时保留逻辑、情绪与原意。不设统一时长、开场秒数或完播率目标，不承诺流量提升。

## 何时执行

选题明确后、展示剪辑稿前，通读相关素材，执行下面五项检查。使用内置[审查模板](../templates/audience-review.md)，在仓库外的视频工程中生成 audience-review.md，与 review.md 一起供用户审阅。模板由 Agent 填写，CLI 不会自动生成或理解其中结论。

执行删留时仍使用现有 edit 和版本检查；不在 story.json 增加标签字段，不改原话或源锚点。标签与理由写入审查文档。用户明确要求直接出新版时，可输出待审版本供查看，不能把制作授权当成对未展示版本的确认，不能继承旧版审批。

## 五项检查

### 1. 开场能否独立理解

检查首句是否依赖上文、现场指代或对讲者的了解。优先使用素材中能独立理解的具体问题、经历或发现。不能为了吸引注意而夸大结论、隐藏条件，或把改写当作原声。必要的新开场只能建议补录或标明编辑文字。

### 2. 价值何时出现

先写清目标观众与标题承诺，再定位问题、关键转折和实际收获第一次出现的位置。背景只有在帮助理解后文时才保留；有价值但与本条主线无关的经历可建议另作选题。

时间必须标明是源素材时间还是成片时间。剪辑前只填估计并注明依据；编译后依据实际区间和字幕映射更新。片尾才出现的方法未必必须提前，但需要说明前面的故事为何值得听。不要为达成固定秒数损伤叙事。

### 3. 句段承担什么功能

按完整意群标注，可多选：背景、观点、例子、限定、情绪、衔接、重复。每条建议附字幕 ID 或源文件与时间区间。

- 背景：删掉后是否会误解后文？后文是否用到？
- 观点：是否提出新的判断，或明确发生了变化？
- 例子：是否使抽象判断可理解，或提供不同视角？
- 限定：是否约束数字、适用范围、确定性或因果？通常必须保留。
- 情绪：表情、停顿、笑声是否使经历可信、形成转折或展示方法？
- 衔接：是否只是现场接话，还是承接了必要的主体、指代或逻辑？
- 重复：是否增加信息、证据、情绪或理解？重复措辞不等于重复功能。

优先删除后文用不到的背景和功能重复的句段。标签仅辅助判断，不触发自动删除；不按口头词黑名单机械剪辑。第一版仍按句级删除，不自动重排、猜测词内拖音边界。

### 4. 删减是否改变原意

逐项检查必要前提、否定、条件、范围、统计限定、引用归属、说话人、观点变化过程与结论。特别核对删后相邻两句是否制造原来不存在的因果或立场。

保留让结论成立的具体例子与情绪，不只留下抽象金句。无法确认原意或边界时保留并标疑点，回查原声；补录和改写是独立建议。字幕、角色标签与辅助画面随实际时间映射同步，不能只剪视频或让 PPT 错配观点。

### 5. 版本变化是否可解释

每次改版填写[版本说明模板](../templates/revision-notes.md)，在工程中生成 revision-notes.md。记录对照文件或版本标识、前后时长、关键删留理由、保留的限定、字幕和 PPT 变化、验证范围与待确认事项。旧稿、审查记录和成片保留；新一轮修改前在工程中按版本归档这两份记录，不能覆盖掉唯一的旧版依据。

结构判断写成预计收益；发布结果单独记录真实来源与统计时间。未采集的播放数据不填数值，可标“未采集”。只有取得真实数据才能描述观测变化；一次变化不证明因果。不能把解码成功写成全片听审通过，也不能把审查文档当成用户审批。

## 虚构场景验收

以下全部为虚构素材，不代表真实用户或传播数据。

| 场景 | 审查应给出的处理 |
|---|---|
| 开场“所以刚才那个方法就行” | 标注依赖前文；寻找可独立理解的原句，找不到则保留必要前提或建议补录 |
| 讲整理书桌前长篇介绍旅行路线，后文没有再引用 | 标背景，建议删除或另作选题，检查删后主体和指代完整 |
| “你刚才说到这个，那我接着说” | 标衔接；确认无必要指代或情绪后可删除，不机械删所有接话 |
| “每天找钥匙十分钟”解释收纳困扰 | 保留具体例子，即使它与抽象观点表达相近 |
| “大概七成吧，我没统计，只是印象” | 数字和限定一起保留，不能剪成统计事实 |
| “我不是建议所有人搬家，只是这次通勤不适合我” | 保留否定、范围与条件，不能只留下“建议所有人搬家” |
| “以前赞成，听完解释后仍不确定” | 保留变化过程，不能剪成最终反对或最终赞成 |
| 演示放松时笑了一下、停顿后再开口 | 按演示和情绪功能判断，不因无台词自动删除 |

## 实施边界

本规范是 Agent 的编辑步骤与审阅产物，不增加 CLI 命令、自动评分、自动重排、自动删句或新审批门槛。保留现有 topic/script/film 审批及哈希规则。真实素材与填写后的记录位于仓库外；仓库仅分发通用规则和空模板。
