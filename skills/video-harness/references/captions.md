# 字幕是可校对的数据

状态：machine=机器识别；compared=对照录音稿；user_confirmed=用户明确给出正确文字；needs_review=听不清或有疑点。对照稿件不等于听审完成。不能由模型置信分数自动标成user_confirmed。

已烧录的字不能靠替换旁边的SRT修改，必须从未加字幕底片重新渲染。保存主文件、源锚点和旧输出；修改一次主文件后同时生成SRT和校对表。

## 接受用户反馈

支持“把原句改为……”“C0025改成……”“00:46附近不对”。先在字幕主文件搜索定位；多处相同文本时给出时间候选。只改文字默认不动时间，不重跑ASR。示例：

```bash
video-harness media patch-caption --project "$PROJECT" --id C0025 --text '但是呢，借助AI' --status user_confirmed
```

上面的底层命令仅用于导入前的素材工程。导入后的工作流改稿必须使用顶层 `edit --changes ... --expected ...`，不得直接改 original/ 或绕过版本确认；工作流原话及源锚点不可改。

在导入前的素材工程中，仅挪时间用`--start`/`--end`，单位为成片秒；工具会拒绝时间重叠和越界，且失败不写主文件。若用户只说“不对”未给正确字，回查对应原声，不擅自选一个通顺版本。

## 校对重点

专名、数字、否定词、转折词、事实/观点/立场等关键概念优先。保留原意；去口头重复需避免改变语气。源录音与文字稿不一致时原声优先；讲者口误不等于字幕错字，补录或改内容需独立处理。

自然断句、最多两行，避免专名被拆；合并过短卡片时保持完整意群及源锚点，不吞掉原句。阅读速度警告仅供复核，不自动删字。参考 [Netflix简体中文字幕](https://partnerhelp.netflixstudios.com/hc/en-us/articles/215986007-Chinese-Simplified-Timed-Text-Style-Guide) 和 [YouTube自动字幕复核说明](https://support.google.com/youtube/answer/6373554?hl=en)，这些是参考而非所有短视频平台统一标准。

map-captions会按词中点选入剪辑区间，并保留词级来源转写；切在半词处仍需人工调整剪辑边界。很长的转写段必须先依据词时间分句，不能让渲染器缩成极小字体掩盖问题。

## 完成表述

回执列明用户确认的更改、对照稿件的部分、仍待听审的句子和实际抽检位置。无法实际听审时说明限制；全片解码成功不是“字幕准确率100%”。

## 删留与观众理解

展示剪辑稿前执行[面向陌生观众的剪辑审查](audience-editing.md)。按句段功能决定删留，不按口头词或停顿机械删除。标签写入工程审查文档，不改变 story.json 结构。保留否定、统计限定、观点变化过程及说话人归属；删后相邻句需重新检查指代、因果和原意。
